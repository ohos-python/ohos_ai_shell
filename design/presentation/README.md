# 对外演示稿

文件：`output/presentation/harmony-ai-shell-product-design.pptx`，路径相对仓库根目录。

用途：向开发者、潜在协作者和技术评审介绍用户体验、核心设计与落地路径。不是产品已发布或目标设备已完成适配的声明。

## 逐页主题

| 页 | 主题 | 讲解重点 |
| --- | --- | --- |
| 1 | Harmony 智能 Shell | 命令与开发环境助手的定位 |
| 2 | 从开发者的一条命令开始 | 用户目标与系统需提供的适配路径 |
| 3 | 主 Shell 与 AI 侧栏 | 普通终端、侧栏解释、用户提交权 |
| 4 | 失败后直接回显 | 纯命令进入输入行，仍需 Enter |
| 5 | 操作前询问 | 能力发现与当前任务询问 |
| 6 | 执行结果 | 主窗口保留真实输出，侧栏说明验证与影响 |
| 7 | 完整任务体验 | 发现、分析、建议、执行与验证 |
| 8 | 会话内部归属 | Scheduler 和 ModelService 从属 AISession |
| 9 | 共享 AI 进程 | 多逻辑会话隔离，故障不结束外部 Shell |
| 10 | 受控 Agent 工作方式 | 真实事实、有限补取、程序校验 |
| 11 | 知识包、证据与配方 | 分发、溯源和动作定义分离 |
| 12 | 端侧与云侧 | 同一上下文底座，不同资源预算 |
| 13 | 回显前检查 | 身份、知识、输入和命令约束 |
| 14 | 实施里程碑 | 先证明无模型安全闭环，再接模型 |
| 15 | 当前交付与下一阶段 | 设计和契约已整理，产品与真机待实现 |
| 16 | 下一步协作 | 目标设备验证与首批可信配方 |

## 讲解边界

- 界面图来自此前项目场景设计，是概念示意，不是真机截图。
- 不宣称某个包、运行时或模型已经完成 Harmony 适配。
- 不使用未经实测的成功率、延迟、内存收益或准确率提升数据。
- 生产签名、可信配方、更新机制、输入桥和运行时仍有实施工作。
- 所有模块遵循用户 Enter 执行，不展示模型自主执行脚本的路径。

## 源文件与编辑

`build_deck.mjs` 使用 JavaScript 和 `@oai/artifact-tool` 构建。文字和表格为原生 PPT 对象，截图和历史图解为图片，可在 PowerPoint 中替换。

构建脚本依赖提供 Presentation API 和校验器的制作环境，通过 `SKILL_DIR`、`RUNTIME_NODE_MODULES`、`RUNTIME_PYTHON` 接入；它不是目标 Shell 的构建入口，也不要求产品开发者安装这些制作工具。没有该环境时可以直接编辑交付的 PPTX。

制作字体为 Arial Unicode MS。查看环境缺少该字体时，应在演示软件中替换为可用中文字体并检查换行。

`assets/` 的三张 TUI 素材来自既有设计，架构页使用 `output/diagrams/session-architecture/03-shared-ai-process.png`。各页备注记录了对应的本地设计来源与限制。
